Why: the user remeshed through Meshy AI and quality dropped a lot, so they asked to rig the **raw** model first and remesh later themselves.
Source: `blender-ninja/new_ninja_no_hood/Meshy_AI_Unmasked_Male_Ninja_T_1019103458_image-to-3d-texture.glb` (400,657 verts / 750,392 tris, 3 JPEG textures, no skin, **T-pose, 1.90 m, centred on the origin**). The `…104746…` file is the 18,887-tri remesh, `…All_Animations.glb` its Mixamo-rigged version (what the first no-hood swap used).

## What was done
- **Same bind pose as `ninja.glb`** (it is also a T-pose, x ±0.79): the raw only needs `scale = 1.75 / (maxY − minY) = 0.92093873` and a shift so the feet sit at y = 0 — no re-posing. Blender's `bound_box` of the imported *posed* object lies about this; read vertex coordinates / the glb `POSITION` min/max instead.
- **Weights** (Blender scene `RawRig` in `blender-ninja/new_ninja_hires_rig.blend`; objects `RR_Armature` = current 70-joint rig, `RR_Src` = current mesh, `RR_Hi` = the raw): nearest point on the current mesh's surface (BVH) → barycentric blend of its 3 vertices' weights, top 4 kept and renormalised. Median surface distance 2.6 mm, p99 1.7 cm, max 4.4 cm. Every raw vertex has weights, sums = 1.
- **Export = `tools/graft_hires.py`**, not the Blender glTF exporter: it keeps nodes / skin / inverse-bind matrices / the `Walking`+`Running` clips (1.0333 / 0.6333 s) / material of `assets/ninja.glb` byte-for-byte and swaps in the raw mesh, the weights (dumped from Blender: `dump_weights.npy` rows in raw vertex order — Blender's importer keeps the glb vertex order exactly, checked with `--check-co`, max diff 0.0) and the raw's three images. **Image order differs**: raw = [baseColor, metallicRoughness, normal], `ninja.glb` expects [normal, baseColor, metallicRoughness] — the script reorders them by following the material. It writes uint32 indices, no `TANGENT` (three derives tangents; a zero tangent turns the surface black), then run `add_outline_normals.py` LAST (done).
- First output was `assets/ninja-hires-test.glb` (loaded with `/?motionOverlay=1&model=/assets/…glb&v=N`; `model=` only works together with `motionOverlay`). numpy lives in the user site: run the scripts with plain `python3` (not `-I`).

## Step 2 — rebuilt hands grafted onto the raw body (same day, user chose this over accepting the hand FAIL)
Why: the raw hand penetrated the hilt (`actual hand mesh clears hilt and guard` FAIL, −14.5 mm, 54k samples): the grip solvers were solved for the rebuilt hand, not the raw one. (Raw fingers are NOT shorter — tips at ~18.5 cm from the wrist like the rebuilt hand — they just have another shape/knuckle layout.)

- **Hands:** welded copy of `RR_Src` (`remove_doubles` 1e-5 — the glb/Blender import splits verts at UV seams, so islands only show after welding), keep the two islands with |x| > 0.7 (8,210 faces each; the glove cuff runs ~9 cm up the forearm, radius ~24 mm, inside the raw sleeve's 29–50 mm), smooth shaded, vertex groups by name, joined into `RR_Combo` (material 0; no extra slot).
- **Texture:** the rebuilt hands use two flat UV patches of the OLD atlas (glove px u 3249–3283 / v 3092–3144, skin u 1506–1529 / v 2567–2619, v from bottom). The raw atlas is 71 % covered, so `tools/paint_hand_patches.py` paints two flat discs into the biggest free areas (found by rasterising the raw UVs at 2048 and a distance transform: (1082,1450) r101 and (1732,2928) r86, y from top) and the hand UVs are remapped affinely into 56×80 / 40×80 px rects inside them (not degenerate → no zero-derivative normal-map NaN). Colours = medians of the raw's own texels: skin (217,166,145), cloth (35,38,39), flat normal (127,126,254), MR cloth (255,125,3) / skin (255,163,0). Base/normal/MR are re-encoded JPEG q95 4:4:4.
- **Export:** dump from Blender (`combo_dump.npz`: positions, per-loop vertex/uv/corner-normal, loop triangles, dense weights; names json) → `tools/graft_mesh.py ORIG DUMP_DIR OUT` splits vertices by (vertex, uv, normal) like the glTF exporter, converts (x,y,z)→(x,z,−y), v→1−v, remaps joints by name, reuses the ORIG skin/clips/material; then `add_outline_normals.py` last. Result `assets/ninja-hires-test.glb`: 389,964 verts / 731,584 tris, 70 joints. (`graft_hires.py` = the first, raw-mesh-only version, now superseded.) Blender copy: `blender-ninja/new_ninja_hires_rig.blend` (scene `RawRig`, objects `RR_Combo`, `RR_Hi` hidden, `RR_Src` hidden).
- **Result:** `m.run()` **0 FAIL** (107 PASS lines): hilt penetrating samples 0, guard 0, min hilt gap −1.6 mm (tolerance 2), hand skin wraps the hilt ≥290° (min 150°). `m.views()` run / walk / combo looked at from front/right/back/left: fingerless gloves + bare fingers read correctly, no seam or tear at the wrist, grip on the hilt through beats 1–3 and the finisher, shoulders level (run swing −3.1…−2°, torso roll ±0.1°, combo roll up to 5.5° = the lunge).

## Cache incident (2026-10-22, user: "both hands badly distorted" in /debug/ref-overlay.html, left standing hand and right grip)
In Chrome driven by the MCP the same config (bottom, idle, spin 38, tilt 2, scale 1.36, clip 11/7, side) showed the raw hands gripping fine, so the user's browser was running a mismatched pair: the server sent no `Cache-Control` for `ninja.glb`/`index.html`, and the glb changed three times that day. Reproduced the failure by loading the OLD client (backup `index.html`) with the NEW glb: fingers stick out of the hilt, nothing wraps. Fixes: `loadNinja()` fetch `{cache:'no-cache'}`; `server/main.go` `noCache()` middleware (needs a restart of `go run .`). Also learned: `ref-overlay.html`'s `refOverlay.set()` does not move the page's sliders — drive the inputs (`input`/`change` events) when you want the UI and the render in sync; `thumb_landmark_solver` on the raw hand (targets tip (338,342), ip (362,262)) leaves cost ≈ 19.8k: the raw thumb's base sits ~2.5 cm farther from the tsuba than the reference, so the thumb lies on top of the hilt toward the guard instead of tucking beside the index — not applied to `FIST.thumbQR` yet.

## Step 4 — thin hands (user chose option 2, 2026-10-22 night): `assets/ninja.glb` = raw body with RESHAPED raw hands

Backup of the pre-thin build + client: `assets/raw/backup-before-thin-hands-2026-10-22/`.
- **GOTCHA that cost two scans (read this before scanning a grip live):** `ringData()` reads the hilt axis via `runCurlAxis()` → the module-level `RUN_HOLD`, and `regrip()` does NOT refresh it. After changing `GRIP_CFG.R.phi/tilt/pt` live you must `Object.assign(__iso.RUN_HOLD, __iso.makeGrip(__iso.GRIP_CFG.R))`; otherwise the ring planes stay on the page-load axis while the hilt moved and every measurement is inconsistent with the file state (symptom: 0 penetrating samples in the session, ~1,100 after a fresh load). Always confirm a candidate with a fresh load of `/debug/ref-overlay.html`. Other traps: `ring_solver.solve` may return no `ang` for a finger (guard); finger poses respond instantly (no SOD lag), but the hand seat needs ~300 settle frames; the overlay camera is attached to the hand (rolling the hand about the hilt changes nothing in the picture).
